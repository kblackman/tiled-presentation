Round two

What I'd bring back to Tiled, and what I'd do differently this time.

Five commitments for Tiled, shaped by what I've learned since I left.

01Partnership

I'm here to be a partner and a resource, not a bottleneck.

I've heard the concern that design could slow things down again. That was true when engineering had to wait on finished designs, and I don't want to bring it back. Everyone should keep the agency to build and ship. I won't be a gate that work has to pass through before it goes out. Instead, I'll keep an eye on what ships and make sure it stays on brand with solid UX. AI now lets everyone on the team contribute ideas and visuals to the product. It also lets designers like me make small changes in the codebase. I see that as an even trade. Over time, I'd like to earn engineering's trust to handle minor UI and design system fixes myself, so their focus can stay on the bigger work. And nothing has to be perfect at launch.

02Function

Function before form.

If you've worked with me, you know how much pride I take in craft. Some of you have been through rounds of my pixel-level feedback before a launch. I still care about craft, but how I work has changed. I truly feel that function should come before form almost every time. It doesn't matter how good something looks if it doesn't solve the user's problem or doesn't work well. I've built things where craft came first and function second, and it showed. Now function leads, and polish follows.

03Advocacy

Let users make the case.

Function first only works if we know what users actually need. I used to decide that by assumption, and customer feedback was a nice-to-have when we could get it. Now I ground decisions in data wherever I can. That might mean usage data in Looker, usability testing on a new feature, or interviews about an existing one we're updating. For a net-new idea, it means asking users before we spend the time to build it. Real feedback becomes the proof that an idea is worth the investment.

04Outcomes

Launch is the halfway point.

I don't want to launch features just to launch them. Every project should start from a metric or business goal we agree on up front. After launch, I'll stay with it and track whether we hit that goal. If it falls short, I'll bring a plan to adjust. Not every gap is worth chasing, so we'd decide together what's worth fixing and what isn't.

05Enablement

Make it easier to build on-brand
by default.

Everyone at Tiled can build now, and that's a strength worth protecting. The next step is making sure what gets built starts out on brand. I'd document our design system in a form AI tools can actually read, so that components, spacing, and patterns come out right the first time. I've been testing how well AI agents follow an existing design system, and the right context files make a real difference. Fewer fixes after launch means more time for everyone to build.

I'm not coming back to work the way I used to. I'm coming back to work the way Tiled works now, and to help make it even better.

I'd love to hear what's ahead on the roadmap, and where you think I could help most.
